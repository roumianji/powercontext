## 二、技术限制分析

### Qoder Sites 平台能力

根据官方文档检查，Qoder Sites 的技术栈如下：

| 组件 | 技术 | 说明 |
|------|------|------|
| **前端** | 静态 HTML/CSS/JS | 支持 React/Vue 等框架打包后的静态文件 |
| **后端函数** | Deno Edge Runtime | TypeScript/JavaScript，运行在边缘节点 |
| **数据库** | Supabase (PostgreSQL) | 云数据库，通过 Supabase JS SDK 访问 |
| **部署** | 自动 HTTPS + CDN | 公网可访问，无需额外配置 |

**关键限制：**
1. **Functions 运行时是 Deno（JavaScript/TypeScript）**，不支持 Python
2. **数据库是 Supabase**，不支持 seekdb
3. **seekdb 是 Python 嵌入式数据库**（`pylibseekdb`），需要 Python 进程和持久化文件系统访问

### seekdb 的技术特性

```python
# seekdb 的工作方式（来自 database.py）
import pylibseekdb
import pymysql

with pylibseekdb.open("data/studylog.seekdb") as runtime:
    # 启动本地嵌入式数据库运行时
    # 返回 MySQL 协议连接参数
    conn = pymysql.connect(**runtime.connection_options())
```

**seekdb 依赖：**
- Python 3.10+ 进程
- 本地文件系统（`.seekdb` 数据文件）
- `pylibseekdb` 库（OceanBase 嵌入式引擎）
- `pymysql` 驱动（MySQL 协议）

**无法在 Qoder Sites Functions 中运行的原因：**
1. Deno 无法导入 Python 库
2. Edge Runtime 无持久化文件系统访问
3. seekdb 需要本地进程启动，不是远程数据库服务

## 三、可行的部署方案

### 方案 A：分离式架构（推荐）

```
┌─────────────────────────────────────────────────────────┐
│  Qoder Sites (前端)                                      │
│  - 静态 HTML/CSS/JS                                      │
│  - 调用后端 API                                          │
│  - 公网访问：https://studylog-xxx.qoder.zone            │
└────────────────────┬────────────────────────────────────┘
                     │ HTTP API
                     ▼
┌─────────────────────────────────────────────────────────┐
│  独立后端服务器（需要自行部署）                            │
│  - Flask + seekdb                                        │
│  - 公网 IP 或域名                                        │
│  - 例如：阿里云 ECS / 腾讯云 CVM / 自建服务器            │
│  - API 地址：https://api.yourdomain.com                  │
└─────────────────────────────────────────────────────────┘
```

**优点：**
- 保留 seekdb 作为实际数据存储（符合赛事要求）
- 前端通过 Qoder Sites 发布，自动 HTTPS + CDN
- 后端完全控制，可优化性能

**缺点：**
- 需要额外的服务器资源和运维
- 需要配置 CORS、API 认证等
- 部署复杂度增加

**实施步骤：**
1. 在云服务器部署 Flask + seekdb 应用
2. 配置 Nginx 反向代理 + HTTPS
3. 修改前端代码，调用远程 API 而非本地 Flask
4. 更新 Qoder Sites 并重新发布

### 方案 B：内网穿透（临时测试）

```
本地 Flask (127.0.0.1:5100) 
    ↓
内网穿透工具 (ngrok / frp / cloudflared)
    ↓
公网临时 URL (https://xxx.ngrok.io)
    ↓
Qoder Sites 前端调用该 URL
```

**优点：**
- 快速验证，无需服务器
- 保留 seekdb

**缺点：**
- 临时 URL，不稳定
- 依赖第三方服务
- 不适合生产环境

**适用场景：** 演示、测试、开发调试

### 方案 C：替换数据库（不符合要求）

使用 Qoder Sites Functions + Supabase 替代 Flask + seekdb。

**优点：**
- 完全在 Qoder Sites 平台内完成
- 无需额外服务器
- 自动扩缩容

**缺点：**
- ❌ **违反赛事要求**：必须使用 seekdb
- ❌ 需要重写所有数据库层代码
- ❌ 失去 seekdb 的特性展示

**结论：** 不推荐，不符合题目要求。

## 七、结论

**核心问题：** Qoder Sites 平台不支持 Python 后端和 seekdb 数据库，无法直接部署完整的 Flask + seekdb 应用。

**可行方案：** 采用分离式架构，Qoder Sites 作为前端，独立服务器部署 Flask + seekdb 后端。

**当前可完成：** 加强本地测试、完善文档、代码改进、Git 提交。

**需要外部资源：** 部署公网后端服务器，实现完整的端到端应用。

**建议：** 先完成当前可执行的工作，然后根据实际情况决定是否部署外部服务器。如果赛事要求必须公网可访问，则需要准备服务器资源。
